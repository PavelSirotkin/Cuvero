# Cuvero

Cuvero — свободный редактор печатных плат в формате `.lay6` (формат
Sprint-Layout 6.0) и конвертер плат из Altium Designer, KiCad, Eagle и DipTrace.
Плату из другой программы можно открыть, исправить и сохранить в `.lay6`.
Такой файл открывается и в самом Sprint-Layout.

Программа написана на Python и Qt (PySide6) и работает в Windows, Linux
и macOS. Интерфейс на русском языке. Написано с использованием ИИ-ассистента
Claude (Anthropic); результат проверялся на реальных платах и в исходных
программах.

## Конвертер

«Файл → Открыть» принимает не только `.lay6`, но и платы других программ:

| Программа | Файл | Проверка |
|---|---|---|
| Altium Designer | `.PcbDoc` (двоичный) | сравнение с Gerber, выведенным из Altium |
| KiCad 5–9 | `.kicad_pcb` | сравнение с Gerber из `kicad-cli`: медь 99,2–100 % |
| Eagle 6 и новее | `.brd` (XML) | открытие в Sprint-Layout |
| DipTrace | `.dip` (двоичный) | сравнение с Gerber DipTrace: медь 92–99,8 % для 2–4 слоёв |

Плата открывается как новый проект, исходный файл не меняется. Получается
обычная редактируемая плата, а не картинка:

- контур;
- дорожки и дуги;
- площадки, SMD-площадки и переходы;
- залитые полигоны;
- надписи и шелкография;
- компоненты с обозначением, номиналом и корпусом;
- до четырёх медных слоёв (C1, C2, I1, I2).

Цепи становятся воздушными линиями там, где площадки ещё не соединены медью.

После открытия программа показывает отчёт: что перенесено приближённо и что
пропущено, потому что в формате `.lay6` для этого нет места. Например,
не переносятся механические и сборочные слои, внутренние слои сверх двух
и пазы (они становятся круглыми отверстиями). Подробности по каждой программе —
в [руководстве](MANUAL.md#платы-из-других-программ).

## Редактор

- Открытие и сохранение `.lay6`. Неизменённый проект записывается байт в байт
  так же, как был прочитан.
- Несколько плат в проекте, многослойные платы, автосохранение.
- Рисование:
  - дорожки, площадки, SMD-площадки;
  - окружности, прямоугольники, полигоны, спецформы;
  - текст штриховым шрифтом с кириллицей.
- Правка:
  - выделение, перемещение, поворот, зеркалирование;
  - копирование между платами, группы;
  - отмена и повтор любого действия.
- Компоненты и макросы `.lmk`: библиотека, установка перетаскиванием, сохранение
  выделенного как макроса.
- Панель свойств: правка размеров, формы, зазоров и термобарьеров, в том числе
  у нескольких объектов сразу.
- Связи (воздушные линии), проверка соединений, автотрассировка по связи,
  проверка правил (DRC).
- Автозаливка с зазорами и термобарьерами.
- Вывод на производство:
  - Gerber RS-274X и X2;
  - сверловка Excellon;
  - фрезеровка изоляции HPGL;
  - изображения BMP, JPG, PNG, SVG;
  - печать.
- Импорт Gerber, обмен объектами в текстовом формате Text-IO, мастер
  посадочных мест.

Описание окна и всех команд — в [MANUAL.md](MANUAL.md).

## Установка и запуск

Нужен Python 3.10 или новее.

```sh
python3 -m venv .venv
. .venv/bin/activate          # в Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py                # или: python main.py плата.lay6
```

Без имени файла программа открывает новый проект с пустым полем 160 × 100 мм.

## Сборка программы одним файлом

`build.py` собирает программу одним исполняемым файлом, которому не нужен
Python, с помощью Nuitka:

```sh
python -m pip install nuitka
python build.py              # dist/Cuvero.exe (в Linux — dist/Cuvero)
python build.py --clean      # сначала удалить прежнюю сборку
```

C-компилятор Nuitka в Windows скачивает сама (zig) при первой сборке, в Linux
берёт gcc. Собирать нужно на той системе, для которой нужна программа.

## Как восстановлены форматы

Форматы `.lay6`, `.lmk`, `.PcbDoc` и `.dip` закрыты. Их устройство восстановлено
по самим файлам: образцы открывались в исходных программах, а результат
сравнивался с тем, что эти программы выводят сами (Gerber, текстовый экспорт).
Программы не декомпилировались.

Платы, записанные Cuvero, проверялись открытием в Sprint-Layout 6.0.
Справочник по структуре `.lay6` —
[импорт Sprint-Layout в KiCad](https://docs.kicad.org/doxygen/sprint__layout__parser_8cpp_source.html).

## Для разработчиков

- `main.py` — запуск программы, `build.py` — сборка, `icon.ico` — значок.
- `version.py` — версия программы (вида `0.1`): она видна в заголовке окна
  и в «О программе» и записывается в свойства собранного файла. Её же нужно
  поменять в `pyproject.toml`.
- `core/` — данные платы и форматы файлов, без Qt:
  - `model` — чтение и побайтно точная запись `.lay6`;
  - `objects`, `shapes`, `texts`, `font` — объекты, фигуры, штриховой шрифт;
  - `gerber`, `gerber_read`, `gerber_import`, `drill`, `hpgl` — вывод и импорт;
  - `macros`, `components`, `boards`, `nets`, `textio`, `arrays` — макросы,
    компоненты, новые платы, связи, Text-IO, размножение;
  - `foreign` — общая сборка плат других программ; `altium` и `cfb` — Altium
    (составные файлы OLE); `kicad` и `sexpr` — KiCad; `eagle` — Eagle;
    `diptrace` — DipTrace.
- `ui/` — интерфейс:
  - `main_window`, `board_view`, `render` — главное окно, поле платы,
    отрисовка;
  - `commands` — отменяемые действия;
  - `importers` — открытие плат других программ;
  - диалоги и панели.
- `tests/` — автотесты.

Инструменты проверки ставятся отдельно, настройки лежат в `pyproject.toml`:

```sh
python -m pip install -r requirements-dev.txt
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m unittest discover -s tests -t .
```

Часть тестов сверяет результат с образцами плат и с Gerber других программ.
Образцы в репозиторий не входят, поэтому без них такие тесты пропускаются.
Тесты библиотеки макросов используют папку `MAKROS` из комплекта
Sprint-Layout, если она лежит рядом.
